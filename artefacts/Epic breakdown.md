# Epic breakdown

This file contains a potential breakdown of the product epic. 

The section features contain the feature (without any statement) and the user story gist below them. The user stories have been created from the wiki. 

The features and users stories are expected to be independent of each other. 

Test the epic breakdown using the epic-breakdown skill from the skills folder. Inform if any problem or decision has been ignored from the problems and decisions. 

## 1. Epic

**If we** provide an evidence-led research assistant that finds, connects and explains authoritative UK capital regulatory evidence - with precise inspectable citations, visible source status and effective dates, and explicit uncertainty/conflict signalling
**for** experienced regulatory reporting analysts on the UK capital reporting team preparing for Basel 3.1 (secondary beneficiary: newer analysts learning the research path)
**Then we will** materially reduce the time required to produce a verified, evidence-backed answer **without** reducing evidence quality or increasing unsafe answers

---

## 2. Features

### 2.1. Search

2.1.1 able to search in natural language
2.1.2 Ability to search in both ways. Rule to reporting field and vice versa
2.1.3 cross referencing of various material like definitions, related instructions, relevant changes

### 2.2. Temporal and status awareness

2.2.1 Answers should be aware of authority of the material (final rule, consultation paper, reporting instructions, rulebook)
2.2.2 Answers should be based on the temporal status of the question and documents. An answer should not be superseded by a later regulatory publication
2.2.3 Answers should not overstate authority 

### 2.3. Expression of conflicts and uncertainty

2.3.1 System should express conflicts and clearly present the conflicting sources
2.3.2 System should express uncertainty in case of low confidence of the answer based on search results

### 2.4. Provision of citations

2.4.1 The system should provide the provenance of the answer identify the document, the relevant section or paragraph
2.4.2 The system should never fabricate citations
2.4.3 The excerpts being cited should explain and answer the question in entirety 

### 2.5 Store previous answers

2.5.1 System should store previous answers with the full information like question, answer, citation etc
2.5.2 System should be able to retrieve these answers if requested or if a past question is repeated
2.5.3 Past answers should be marked stale in case of superseding regulations
